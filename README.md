# Yevhenii Muradov — Art · Craft · Design

Двомовний статичний сайт-портфоліо з PHP-обробником контактної форми.

## Структура

- `uk/`, `en/` — готові українські й англійські HTML-сторінки.
- `assets/css/styles.css` — усі дизайн-токени, компоненти та адаптивні стилі.
- `assets/js/` — меню, анімації, фільтр портфоліо та форма.
- `assets/img/` — оптимізовані WebP-фрагменти з дозволеної презентації.
- `api/` — CSRF endpoint і PHP→Telegram обробник.
- `config/config.example.php` — приклад приватної конфігурації.
- `tools/build_site.py` — невеликий локальний генератор повторюваних HTML-сторінок.

Python використовується лише для зручного оновлення HTML під час розробки. На хостингу він не потрібний. Готовий сайт працює на HTML/CSS/JS; PHP потрібний лише формі.

## Локальний перегляд HTML

У корені проєкту:

```bash
python3 -m http.server 8080
```

Відкрити `http://localhost:8080/`.

Форма на цьому сервері не працюватиме, оскільки `http.server` не виконує PHP.

## Локальний перегляд із формою

Якщо PHP встановлено:

```bash
php -S 127.0.0.1:8080
```

Відкрити `http://127.0.0.1:8080/`. За замовчуванням форма працює в чесному `mock`-режимі: дані перевіряються, але Telegram-повідомлення не надсилається.

## Підключення Telegram

Рекомендований варіант — environment variables у конфігурації хостингу:

```text
CONTACT_MODE=telegram
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Для локальної перевірки можна скопіювати `config/config.example.php` у `config/private.php` і заповнити значення. Файл `private.php` ігнорується Git. У production його слід винести за межі публічного каталогу або використовувати лише environment variables.

Секрети ніколи не потрібно додавати в HTML, JavaScript, README чи комітити в Git.

## Редагування контенту

Повторювані дані напрямів і проєктів зберігаються у словниках `SERVICES` і `PROJECTS` у `tools/build_site.py`. Після змін виконати:

```bash
python3 tools/build_site.py
```

Команда оновлює готові статичні HTML-файли. CSS, JS, PHP і зображення вона не перезаписує.

### Додавання проєкту

1. Додати оптимізовані зображення в `assets/img/projects/`.
2. Додати один запис до `PROJECTS` із даними `uk` та `en`.
3. Запустити `python3 tools/build_site.py`.
4. Перевірити картку, обидві детальні сторінки, alt-тексти та мовний перемикач.
5. Перед релізом додати обидві абсолютні адреси до `sitemap.xml`.

## Заміна hero-зображення

Головний hero використовує:

```text
assets/img/brand/hero-wolf.webp
```

Можна замінити файл зі збереженням назви або змінити шлях у `tools/build_site.py` і повторно зібрати HTML.

## Перед перенесенням на Fornex

1. Підтвердити домен і доступну версію PHP (рекомендовано PHP 8.1+).
2. Перевірити наявність PHP cURL і HTTPS.
3. Налаштувати Telegram credentials поза webroot.
4. Для іншого домену оновити `PUBLIC_SITE` у `tools/build_site.py` та URL sitemap у `robots.txt`.
5. Додати production canonical та абсолютні `hreflang` після визначення домену.
6. Завершити юридичні реквізити політики конфіденційності.
7. Перевірити контакти, назви й технічні описи.
8. Увімкнути кешування статичних ресурсів і стиснення на сервері.
9. Повторно протестувати форму без mock-режиму.

## Дані, які ще потрібно уточнити

- фінальний домен і конфігурація Fornex;
- Telegram bot token та `chat_id`;
- остаточні матеріали, обладнання, допуски й виробничі обмеження;
- чи потрібне завантаження вкладень у формі;
- юридичні дані контролера й строк зберігання звернень;
- остаточна біографія та портрет майстра;
- підтверджене написання імені в усіх офіційних матеріалах.

## Важливо про зображення

Поточні кадри підготовлено з наданої PDF-презентації, дозвіл на використання якої підтверджено власником. Для найкращої якості перед production-релізом бажано замінити ключові кадри оригінальними фотографіями у вищій роздільній здатності.
